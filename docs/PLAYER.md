# Archive player

Every episode URL selects an episode in the same shared interface. `/` initially renders the newest public episode and can restore the last saved selection after hydration; `/episodes/<saved-slug>` always selects that episode. The layout and native audio element remain mounted during internal navigation. Artwork, artist/title, description, tracklist, source, and page metadata follow the accepted selection together.

## Listening and navigation

- Fresh loads, refreshes, and new tabs always stay paused. Within 24 hours of the last document visit, restore the current episode and position from this browser's local storage. A matching explicit episode URL restores its position; another explicit episode starts at zero. A root-page restore replaces the address with the saved episode's canonical path. Exactly 24 hours is expired; missing, removed, invalid, or unavailable saved state falls back to the requested/newest public episode at zero.
- Every selection requests the audio's metadata while staying paused unless playback was already active. “Loading audio…” remains until the browser has a finite, positive duration; then paused episodes show “Press Play to listen.” The player requests automatic preloading until metadata arrives and reduces it afterward. While paused, ten seconds without loading progress triggers one automatic retry; another stall displays “Audio is taking longer to load.” with an optional “Retry audio” action. The timeout does not report a media error, pause playback, or cancel a pending Play request. Browsers can defer preloading; late metadata or pressing Play can recover the existing source without a reload. Blocked-play prompts remain intact. Pausing before metadata arrives resumes bounded recovery even without further network progress. Source changes and disposal cancel pending recovery.
- Selecting another episode starts it at zero. Active playback attempts to continue; paused playback stays paused. Selecting the current episode preserves its source, time, and playback state.
- Episode links add browser history entries. Back/Forward selects the addressed episode with the same active/paused rule. Progress never changes the URL.
- Custom controls provide Play/Pause, a full-width seek slider, and Back/Forward 30 seconds. Scrubbing previews a position through playing/buffering changes and commits one seek; Escape or cancellation discards it. Arrow keys seek five seconds, Page Up/Down seek 30, and Home/End select the bounds. Seeks preserve active/paused intent and use actual browser duration and seekable ranges. The selected episode stops at its natural end until the sequencing slice.
- Volume and mute are checked independently against the paused element before playback. Working volume controls use 5% steps and display actual element volume; unmuting zero restores the last nonzero level. Unsupported volume omits its slider and shows “Use your device's volume buttons.” A working mute button remains available independently. Preferences last for the mounted session. The native UI is a fallback until the custom controls attach; one audio element handles both.
- A blocked continuation displays “Press Play to continue.” A media failure exposes “Retry audio”; retry reloads the source paused. An artwork failure leaves the player and content available with a labelled fallback.
- A media failure stops continuation even if the browser still reports active playback. A queued source-reset pause preserves the blocked-play prompt; a listener's pause cancels a pending start through the native `AbortError` outcome.
- Episode selection has one live announcement. The visible playback status is associated with the custom control group and fallback audio through its accessible description, without a second competing live region.
- Artwork opens its original image in a modal dialog, preserving its proportions and limiting it to 90% of the viewport's width and height. Smaller images are not enlarged. The surrounding margin remains available for outside clicks, and the close button stays at the viewport's top right. Outside clicks, the close button, and Escape dismiss it and return focus to the artwork trigger. The page behind the dialog is inert and cannot scroll. Changing episodes dismisses obsolete artwork without replacing the audio element or interrupting playback.
- Episode rows use checked-in 96px WebP thumbnails displayed at 48px, loaded lazily from the application origin. Missing thumbnails never request original artwork. The selected player and enlargement retain the original image. See [thumbnail generation and validation](CONTENT.md#episode-list-thumbnails).
- All 55 imported episodes and 832 tracks are visible through the archive. Counts are derived from public content, without a fixed archive limit. Known, in-range track starts are seek buttons; unavailable tracklists are labelled explicitly. Previous/Next track skip untimed starts and never wrap or change episodes. Previous restarts the current known start after more than three seconds; at three seconds or less it goes to the preceding known start. Before the first timestamp only Next is available. The visible “Current position” marker follows confirmed time, including while paused, and leaves uncertain intervals before untimed rows unhighlighted. Track seeking preserves playback intent, keyboard focus, and the selected mobile tab.

The owner selected **Episodes/Tracklist tabs on mobile on 2026-09-09** after receiving working alternatives. Wider screens show adjacent regions. Tabs support arrow keys and Home/End, expose selection and panel relationships, and leave the player mounted. The comparison switch is removed.

## Data and lifecycle boundaries

`app/middleware/episode.ts` resolves the model before server rendering the shared layout. The application uses the existing public show/list/detail APIs and the server's publication predicate. Nuxt payload state supplies hydration, so it does not trigger another initial request or playback call.

`app/services/episode-page.ts` stages navigation independently of the displayed episode. Requests and route completion callbacks carry generation tokens; obsolete requests cannot overwrite the current model or cancel a newer stage for the same path. Superseded requests are aborted. A failed selection leaves the prior route/player usable and offers retry. Client navigation creates a fresh public-data request for a revisited path, avoiding cached handlers with stale cancellation signals; SSR retains keyed async data and hydration reuses its serialized page model.

`app/services/audio.ts` adapts one existing element and exposes its actual snapshot/events. Metadata readiness is reconciled on `loadedmetadata`, `durationchange`, `progress`, `loadeddata`, `canplay`, and `canplaythrough`. Captured native WebKit loads reported duration `0` during early metadata events; one kept that value through `canplaythrough`, then exposed its positive duration 17 ms later without another media event. Once the browser reports metadata readiness, an unavailable duration is also rechecked every 250 ms. These value checks never reload or pause audio, do not extend the network-retry deadline, and stop once duration is known or the source changes, fails, ends, or is disposed. Browsers deferring metadata entirely do not start this value-check loop. `app/services/player.ts` owns source transitions and playback-promise generations. Browser `play()` makes a pending playback request observable through `paused`; loading a new source and attempting continuation happen together. Queued source-change pause events are ignored while the current element is playing and cannot erase a blocked continuation. Native rejection reasons distinguish a user-cancelled start from blocked playback. Source changes, media failures, and disposal invalidate obsolete play callbacks. `usePodcastPlayer` binds only after mount and disposes the adapter with its owning component.

Server rendering never constructs browser media objects. The layout owns `usePodcastPlayer` and passes its session into the player presentation. Application state is per Nuxt application/request, and the audio element sits outside the changing page. Native time updates drive local persistence; volume/mute observations keep the custom UI aligned with the element. Description HTML comes only from the existing canonical sanitizer; ordinary text uses escaped bindings.

Restoration uses `nurevolution.playback.visit.v1` and `nurevolution.playback.resume.v1`, containing only the last visit instant and one stable episode ID/position/activity instant. Read the old visit before recording a new one. Reloads, new documents, and back/forward-cache returns count as visits; internal routes, playback ticks, and focus do not. Background listening continues; leaving a document pauses it, and a cached return remains paused at that document's own position. Prerendered pages wait for activation. Position saves are throttled to five seconds while playing and flushed on selection, completed seeks, pauses, and dirty page exits. An idle tab does not overwrite newer progress on closure, and another tab's writes never move the live player. No per-episode history, playback authorization, direction, or volume is stored.

Restored position waits for finite native duration and clamps to its actual bounds; restoring at the end does not play. A user pause cancels a queued start. A stalled metadata retry retains the pending restore target; explicit Retry audio starts at zero, paused. Failed seeks show the actual position and a recoverable message. A root restore detail request has a five-second bound and yields to newer manual navigation. A manual selection during root restoration waits for the new route to settle before loading or saving audio; cancellation, failure, or closing during that wait preserves the earlier resume record. Returning from a cached page ignores delayed teardown pauses, so they cannot overwrite newer progress from another tab. Retry saves its reset zero position, and replacement audio under the same stable ID also saves zero. The custom Pause command saves once immediately, or after a pending seek settles. A timed-out paused seek saves actual time with the original pause activity timestamp, preserving newer-tab progress. Its delayed native event and delayed Retry pauses retain their original activity timing; a visible seek failure does not prevent later progress, pause, or end positions from being saved. Storage errors disable persistence for the document without blocking playback. See the [M7 contract](milestones/M07-rich-player-and-restoration.md) for exact visit, tab, seek, and route rules.

## Downloads and old links

The header RSS link and browser feed discovery use the current host’s `/feed/podcast`. Episode/home navigation and thumbnails also use local paths. Deployed artwork/audio and download redirects use the accepted environment’s delivery hosts. Canonical page metadata, copied episode URLs, and the RSS document’s identity/media URLs retain the production hosts. The local Node download fallback still fetches canonical production audio server-side; deployed downloads are handled by Caddy using the environment profile.

Each episode row also has a copy-link button. It copies that episode's canonical public URL, including when browsing a preview or local server, without selecting the episode or affecting playback. A successful copy or clipboard failure shows three seconds of feedback beside the button, falling back to the viewport's top center when the button is offscreen or space is limited. Feedback is announced without moving keyboard focus. On Android, a successful copy instead shows a three-second inline checkmark on the clicked button, avoiding a duplicate popup alongside the system clipboard confirmation. Copy failures retain the visible toast on every platform.

Each episode has a `/downloads/<saved-slug>` link. The endpoint resolves a public episode, fetches its exact canonical HTTPS URL on `podcast.nurevolution.net`, validates status/type/length/encoding, and serves an attachment with the canonical raw basename. It supplies both quoted ASCII and UTF-8 filename parameters, preserving punctuation such as the apostrophe in `bouche_d'incendie`.

The application endpoint supports GET and HEAD; other methods return 405. Unknown or nonpublic slugs return 404 before fetching media. It accepts no request-supplied upstream URL, credentials, filename, or forwarded cookies/authorization. Redirects are rejected. Upstream header waiting is bounded to ten seconds; a healthy full download has no short total-duration timeout. The response uses `no-store` and does not advertise ranges; Range requests receive the complete 200 representation. Playback and RSS retain the original direct media URLs.

The response service streams chunks and verifies the final byte count. The Node handler uses `Readable.fromWeb` and `pipeline` for backpressure and cancellation; H3 v1's default web-stream bridge does not wait for `write()` backpressure. A client disconnect cancels upstream work. Invalid upstream metadata produces a plain 502/504 before success headers; a failed body terminates the connection without appending an error document.

All 55 known `/podcast/...` paths and their single trailing-slash variants redirect with 301 to the saved episode path. Redirects use the shared publication predicate and drop legacy query parameters. Unknown paths are 404; no title/GUID-derived guesses are made. Existing RSS aliases remain in place.

## Verification and deployment handoff

Run **`CI=1 pnpm verify`** for the canonical gate. Focused player/controller, Nuxt presentation/routing, download/redirect, and built-browser tests are also available through the existing Vitest and Playwright commands.

Tests reconcile every episode's SSR metadata/artwork/list/download links and all 832 rendered tracks, every historical redirect, and the complete feed. Browser scenarios cover no initial autoplay, element persistence, active/paused selection, Back/Forward, rapid/stale requests, failed navigation, media retry, responsive tabs, keyboard focus, MP3 decoding/natural completion, and actual attachment saves. Controlled media races remain unit tests; browser integration uses original small fixtures and the production components/streaming handler. CI makes no requests for the large public MP3 bodies and needs no private WordPress files.

Set `NUREVOLUTION_MEDIA_TRACE=1` for a focused browser run to attach bounded native event/duration-read traces to its report. Normal CI runs without that instrumentation. Deterministic regressions exercise both late readiness events and a duration that changes silently after every readiness event.
