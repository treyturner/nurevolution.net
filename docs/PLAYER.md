# Archive player

Every episode URL selects an episode in the same shared interface. `/` initially renders the newest public episode and can restore the last saved selection after hydration; `/episodes/<saved-slug>` always selects that episode. The layout and native audio element remain mounted during internal navigation. Artwork, artist/title, description, tracklist, source, and page metadata follow the accepted selection together.

## Listening and navigation

- Before application initialization, the selected episode displays “Loading player…”. An independent classic script changes this to “Player could not start.” with an adjacent Reload link after fifteen seconds, and clears the warning if initialization succeeds later. The MP3 download remains available; with JavaScript disabled, the same row explains that playback needs JavaScript. This startup deadline is separate from audio metadata/recovery timeouts. These M8 startup changes passed automatic review in PR #56 and partial owner testing on the iPad; the remaining physical acceptance checks are still pending. They have not been deployed.
- While playing, the player status shows `Playing <current track>/<track total>: <track artist> - <track title>` using the same confirmed track as the tracklist highlight. It follows playback and seeks automatically; missing tracklists, missing timestamps, or uncertain gaps keep the plain `Playing` status. Audio, seeking, saved-position, and episode-navigation failures replace the normal status in the same row, using coral text and a compact Retry action where recovery is available. The row reserves three lines and its action space across states; messages remain readable and wrap further if needed for enlarged text. Status changes are announced politely to assistive technology.
- Fresh loads, refreshes, and new tabs always stay paused. Without a `t` parameter, within 24 hours of the last document visit, restore the current episode and position from this browser's local storage. A matching explicit episode URL restores its position; another explicit episode starts at zero. A root-page restore replaces the address with the saved episode's canonical path. Exactly 24 hours is expired; missing, removed, invalid, or unavailable saved state falls back to the requested/newest public episode at zero.
- Every selection requests the audio's metadata while staying paused unless playback was already active. “Loading audio…” remains until the browser has a finite, positive duration; then paused episodes show “Press Play to listen.” The player requests automatic preloading until metadata arrives and reduces it afterward. While paused, fifteen seconds without loading progress triggers one automatic retry; another fifteen-second stall displays “Audio is taking longer to load.” with an optional “Retry audio” action. The timeout does not report a media error, pause playback, or cancel a pending Play request. Browsers can defer preloading; late metadata or pressing Play can recover the existing source without a reload. Blocked-play prompts remain intact. Pausing before metadata arrives resumes bounded recovery even without further network progress. Source changes and disposal cancel pending recovery.
- While playback is active or buffering, manually choosing a different episode (including Previous/Next episode and browser Back/Forward) asks “Stop playback to change episodes?”. “Keep listening”, Escape, or clicking the backdrop cancels without loading the target or stopping the current audio; “Change episode” accepts. The dialog names the target episode, keeps playback running while waiting, locks scrolling behind it, and has no decision timeout. Clicking its interior padding keeps it open; only an actual backdrop click cancels. Paused selections, selecting the current episode, and automatic advancement after completion need no confirmation. Closing or refreshing the tab uses normal browser behavior and the saved playback position.
- Selecting another episode starts it at zero. Active playback attempts to continue; paused playback stays paused. Selecting the current episode preserves its source, time, and playback state.
- The button at the top right of Episodes is the only order control: “Sort: Newest” (the default) or “Sort: Oldest” states the current order, and its tooltip names the other order. Next episode and automatic playback move down the displayed list; Previous episode moves up. Both wrap at the ends. Flipping the sort preserves the selected episode and playback position. Before playback has ever started in the mounted session, an unplayed top episode follows the new top in either direction; an outstanding Play request or any actual playback in this session keeps the selection, including when paused later. The sort control is unavailable during initial restoration or pending navigation and for fewer than two episodes. Sort order lasts for this mounted session and resets to newest first on a new document. A sort-induced selection uses ordinary navigation history and stays paused. Automatic transitions replace the current history entry and preserve the mobile tab and focus. They require real active playback: a paused seek to the end cannot advance. Pause during the next detail request or buffering cancels continuation, while an already pending manual selection wins over automatic completion. A failed target stops with a recovery message; a blocked Play requires another gesture. One-episode archives restart without reloading the source or adding history; missing/empty selections disable episode navigation.
- Episode links add browser history entries. Back/Forward selects the addressed episode with the same active/paused rule. Progress never changes the URL. Links in episode descriptions open in a separate tab, keeping the original player mounted and playing.
- The Tracklist header's “Show: Duration” / “Show: Timestamp” button matches the episode sort control and names the opposite view in its tooltip. Each new page load defaults to durations; the choice survives internal episode navigation. Durations use the next track's exact start, or the catalog episode duration for the final track, and truncate to whole seconds in `m:ss`. Unknown boundaries show `-:-`; untimed rows remain without a time. Switching the display preserves playback, selection, and the exact timestamp used for seeking.
- The joined transport row provides Previous episode, Previous track, Back 30 seconds, Play/Pause, Forward 30 seconds, Next track, and Next episode in that order. The 30-second actions use chevrons; all icon controls retain accessible names and hover descriptions. The transport buttons share one row with narrower widths; player widths below 320px hide the two 30-second buttons, preserving at least 44px button targets, including with enlarged text. The remaining five controls keep their order and the skip buttons return when space permits. A full-width seek slider sits above the row. Scrubbing previews a position through playing/buffering changes and commits one seek; Escape or cancellation discards it. Arrow keys seek five seconds, Page Up/Down seek 30, and Home/End select the bounds. Seeks preserve active/paused intent and use actual browser duration and seekable ranges. Natural completion moves down the displayed episode list.
- The mute icon and volume slider share a rounded control, aligned right beside transport and left when wrapped below it. The slider shrinks to a usable minimum before wrapping. Its icon distinguishes muted, zero volume, and one to three waves across the remaining volume range. Volume and mute are checked independently against the paused element before playback. Working volume controls use 5% steps and display actual element volume; unmuting zero restores the last nonzero level. Unsupported volume omits its slider and shows “Use your device's volume buttons.” A working mute button remains available independently. Preferences last for the mounted session. The native UI is a fallback until the custom controls attach; one audio element handles both.
- A blocked continuation displays “Press Play to continue.” A media failure exposes “Retry audio”; retry reloads the source paused. An artwork failure leaves the player and content available with a labelled fallback.
- A media failure stops continuation even if the browser still reports active playback. A queued source-reset pause preserves the blocked-play prompt; a listener's pause cancels a pending start through the native `AbortError` outcome.
- Episode selection has one live announcement. The visible playback status is associated with the custom control group and fallback audio through its accessible description, without a second competing live region.
- Artwork opens its original image in a modal dialog, preserving its proportions and limiting it to 90% of the viewport's width and height. Smaller images are not enlarged. The surrounding margin remains available for outside clicks, and the close button stays at the viewport's top right. Outside clicks, the close button, and Escape dismiss it and return focus to the artwork trigger. The page behind the dialog is inert and cannot scroll. Changing episodes dismisses obsolete artwork without replacing the audio element or interrupting playback.
- Episode rows use checked-in 96px WebP thumbnails displayed at 48px, loaded lazily from the application origin. Missing thumbnails never request original artwork. The selected player and enlargement retain the original image. See [thumbnail generation and validation](CONTENT.md#episode-list-thumbnails).
- All 55 imported episodes and 832 tracks are visible through the archive. Counts are derived from public content, without a fixed archive limit. Known, in-range track starts are seek buttons; unavailable tracklists are labelled explicitly. Previous/Next track skip untimed starts and never wrap or change episodes. Previous restarts the current known start after more than three seconds; at three seconds or less it goes to the preceding known start. Before the first timestamp only Next is available. When no usable timestamps exist, both track-control tooltips say “Unavailable for this episode.” The current-track highlight follows confirmed time and reserves equal space on every row to keep columns aligned. Track-boundary comparisons allow 10 microseconds of native clock rounding; authored timestamps and seek targets retain their full precision. After a confirmed seek, Safari 14 can briefly roll its playback clock back by a few tenths of a second when playback starts. Track identity and Previous/Next track retain that confirmed boundary through a rollback of at most half a second, for at most one second after playback clock updates resume. Advancing past the boundary, a larger jump, another seek, or a source reset immediately releases that guard. The playhead, saved positions, natural track boundaries, and authored seek targets remain unchanged. Beside the timestamp, “now playing” and a five-band equalizer fade in and out together over one second. Paused tracks retain only their highlight. Skips within the current track keep the indicator visible through buffering; changing tracks fades between rows. Reduced-motion preferences disable both the fade and equalizer animation. Episode and track highlights remain visible on hover and share a three-pixel width; square track hover backgrounds extend to the highlight with padded content. Narrow tracklists move this metadata below the track details. Uncertain intervals before untimed rows remain unhighlighted. Clicking the highlighted current track toggles Play/Pause at the current position without seeking, including cancelling a pending Play request; its accessible name follows the action. At the exact episode end, the final row instead offers a seek to that track’s start, staying paused until Play is chosen. Clicking another timed track seeks to its start and preserves playback intent, keyboard focus, and the selected mobile tab.

The owner selected **Episodes/Tracklist tabs on mobile on 2026-09-09** after receiving working alternatives. Wider screens show adjacent regions. Tabs support arrow keys and Home/End, expose selection and panel relationships, and leave the player mounted. The comparison switch is removed.

## Data and lifecycle boundaries

`app/middleware/episode.ts` resolves the model before server rendering the shared layout. The application uses the existing public show/list/detail APIs and the server's publication predicate. Nuxt payload state supplies hydration, so it does not trigger another initial request or playback call.

`app/services/episode-page.ts` stages navigation independently of the displayed episode. Requests and route completion callbacks carry generation tokens; obsolete requests cannot overwrite the current model or cancel a newer stage for the same path. Superseded requests are aborted. A failed selection leaves the prior route/player usable and offers retry. Client navigation creates a fresh public-data request for a revisited path, avoiding cached handlers with stale cancellation signals; SSR retains keyed async data and hydration reuses its serialized page model.

`app/services/audio.ts` adapts one existing element and exposes its actual snapshot/events. Metadata readiness is reconciled on `loadedmetadata`, `durationchange`, `progress`, `loadeddata`, `canplay`, and `canplaythrough`. Captured native WebKit loads reported duration `0` during early metadata events; one kept that value through `canplaythrough`, then exposed its positive duration 17 ms later without another media event. Once the browser reports metadata readiness, an unavailable duration is also rechecked every 250 ms. These value checks never reload or pause audio, do not extend the network-retry deadline, and stop once duration is known or the source changes, fails, ends, or is disposed. Browsers deferring metadata entirely do not start this value-check loop. `app/services/player.ts` owns source transitions, playback-promise generations, and a once-per-run eligible-end callback. `episode-sequencing.ts` resolves ordered neighbors and coordinates route completion with cancellable continuation; the browser navigation composable owns bounded route requests. Browser `play()` makes a pending playback request observable through `paused`; loading a new source and attempting continuation happen together. Queued source-change pause events are ignored while the current element is playing and cannot erase a blocked continuation. Native rejection reasons distinguish a user-cancelled start from blocked playback. Source changes, media failures, and disposal invalidate obsolete play callbacks. `usePodcastPlayer` binds only after mount and disposes the adapter with its owning component.

Server rendering never constructs browser media objects. The layout owns `usePodcastPlayer` and passes its session into the player presentation. Application state is per Nuxt application/request, and the audio element sits outside the changing page. Native time updates drive local persistence; volume/mute observations keep the custom UI aligned with the element. Description HTML comes only from the existing canonical sanitizer; ordinary text uses escaped bindings.

Restoration uses `nurevolution.playback.visit.v1` and `nurevolution.playback.resume.v1`, containing only the last visit instant and one stable episode ID/position/activity instant. Read the old visit before recording a new one. Reloads, new documents, and back/forward-cache returns count as visits; internal routes, playback ticks, and focus do not. Background listening continues; leaving a document pauses it, and a cached return remains paused at that document's own position. Prerendered pages wait for activation. Position saves are throttled to five seconds while playing and flushed on selection, completed seeks, pauses, and dirty page exits. An idle tab does not overwrite newer progress on closure, and another tab's writes never move the live player. No per-episode history, playback authorization, direction, or volume is stored.

Restored position waits for finite native duration and clamps to its actual bounds; restoring at the end does not play. A user pause cancels a queued start. A stalled metadata retry retains the pending restore target; explicit Retry audio starts at zero, paused. Failed seeks show the actual position and a recoverable message. A root restore detail request has a five-second bound and yields to newer manual navigation. A manual selection during root restoration waits for the new route to settle before loading or saving audio; cancellation, failure, or closing during that wait preserves the earlier resume record. Returning from a cached page ignores delayed teardown pauses, so they cannot overwrite newer progress from another tab. Retry saves its reset zero position, and replacement audio under the same stable ID also saves zero. The custom Pause command saves once immediately, or after a pending seek settles. A timed-out paused seek saves actual time with the original pause activity timestamp, preserving newer-tab progress. Its delayed native event and delayed Retry pauses retain their original activity timing; a visible seek failure does not prevent later progress, pause, or end positions from being saved. Storage errors disable persistence for the document without blocking playback. See the [M7 contract](milestones/M07-rich-player-and-restoration.md) for exact visit, tab, seek, and route rules.

## Device media controls

The local M8 Media Session slice connects supported lock-screen, headset, and media-key actions to the existing player controller. Play, Pause, and Stop preserve the episode; Stop pauses in place. Skip defaults to 30 seconds unless the device supplies a finite positive offset. Seek To uses the exact supplied time and the ordinary bounds. Previous/Next track use the same known boundaries and three-second restart rule as the page, never an episode fallback. Unavailable track actions are removed. Pending episode selection freezes source-changing actions while keeping Pause available.

System metadata follows the known current track (track title/artist, with `Episode artist - Episode title` as album), or falls back to episode title/artist and the show title when the track is unknown. Artwork follows the configured development delivery origin. The system timeline always remains episode-relative. Confirmed positions update at most once per second during normal ticks, immediately after completed seeks and playback/source changes, and never advertise an unfinished seek target. Missing duration clears the position state.

All APIs are optional and individual unsupported actions/properties are isolated. Backgrounding does not pause playback. Page exit suspends and clears the session; BFCache return rebuilds it paused, and final disposal removes handlers/metadata. Automated adapter, mounted-player, and browser checks cover the implementation; actual lock-screen/headset acceptance remains pending. These local changes have not been deployed.

## Downloads and old links

### Timestamp sharing

The M8 sharing slice puts `Copy timestamp link` in the playhead context menu and a separate copy button on each timed track. Open the menu by right-clicking the playhead thumb, holding a stationary touch on that thumb for 600 ms, or pressing Shift+F10/the Context Menu key while the slider has focus. Escape, Tab, outside interaction, scrolling, resizing, and source changes dismiss the menu. The rail and time labels do not open the copy menu. The menu is positioned above the thumb. Touch activation extends to a 32-pixel area around the visible thumb; mouse activation remains restricted to the thumb itself. A long press that begins on the thumb cancels the scrub preview without seeking; ordinary taps and drags retain their existing seek behavior. Both copy the episode path under the current browser origin with `?t=<seconds>` (including its scheme, hostname, and port) and show `Timestamp link copied`, without seeking or pausing. Track buttons use the original fractional start; the menu action samples the pending seek or current playhead when activated. Untimed rows have no copy button. Clipboard failure uses the existing error toast and never navigates. The copy icon sits after the track title at the same size and color, with tooltip `Copy track link` and a detailed accessible name. These changes are included in PR #56 and the workspace preview; no M8 deployment has occurred.

On canonical episode routes, a single unsigned decimal `t` overrides the remembered position, waits for metadata, and starts paused. Zero is explicit; excessive positions clamp to the measured duration. Invalid/empty/repeated values suppress restoration, start at zero, and show `Invalid timestamp; starting at 0:00.` until playback or another seek. Root ignores `t` and retains ordinary restoration. Parsing is bounded to 64 characters and the safe-integer maximum; generated values retain numeric precision and use plain decimals, with unsupported values refused rather than rounded. Canonical page identity remains the plain episode URL.

An accepted same-episode time link pauses and seeks through the existing controller without reloading its source. A different episode still requires confirmation while playing, and acceptance opens the shared time paused. Cancel preserves playback and the route. Back/Forward reapplies changed time parameters once; other query/hash changes leave playback alone. Generation checks discard obsolete data responses and seeks. A failed shared seek says `Could not seek to the shared position. Try again.` in the existing status row.

### Episode, feed, and download links

The header RSS button copies the canonical public feed URL without navigating or interrupting playback. It shows an “RSS URL copied” toast for three seconds on success, using the same placement and accessible announcement as episode-copy feedback. Its accessible name includes the visible “Subscribe via RSS” label and initially describes the native new-tab link; it offers copying once the browser confirms clipboard support. The underlying canonical feed link opens in a new tab when JavaScript or the Clipboard API is unavailable, and modified clicks retain ordinary link behavior. If copying is denied, the first activation shows an error; the next activation opens the feed in a new tab, as explained by the feedback and updated tooltip, preserving the original episode and playback. Its text hides on narrow screens, keeping the icon beside the branding. Browser feed discovery uses the current host’s `/feed/podcast`. Episode/home navigation and thumbnails also use local paths. Deployed artwork/audio and download redirects use the accepted environment’s delivery hosts. Canonical page metadata, ordinary episode/RSS copy links, and the RSS document’s identity/media URLs retain the production hosts. Timestamp-copy links use the current browser origin so preview links reopen the preview. The local Node download fallback still fetches canonical production audio server-side; deployed downloads are handled by Caddy using the environment profile.

Each episode row also has a copy-link button. It copies that episode's canonical public URL, including when browsing a preview or local server, without selecting the episode or affecting playback. A successful copy or clipboard failure shows three seconds of feedback beside the button, falling back to the viewport's top center when the button is offscreen or space is limited. Feedback is announced without moving keyboard focus. On Android, successful copies from every copy action (episode, track, playhead, and RSS) suppress the visible site toast because Android supplies clipboard confirmation. Accessible status announcements remain, and episode buttons also show their existing three-second inline checkmark. Copy failures retain the visible toast on every platform. Track-copy buttons suppress the native tap highlight while retaining keyboard focus styling.

Each episode has a `/downloads/<saved-slug>` link. The endpoint resolves a public episode, fetches its exact canonical HTTPS URL on `podcast.nurevolution.net`, validates status/type/length/encoding, and serves an attachment with the canonical raw basename. It supplies both quoted ASCII and UTF-8 filename parameters, preserving punctuation such as the apostrophe in `bouche_d'incendie`.

The application endpoint supports GET and HEAD; other methods return 405. Unknown or nonpublic slugs return 404 before fetching media. It accepts no request-supplied upstream URL, credentials, filename, or forwarded cookies/authorization. Redirects are rejected. Upstream header waiting is bounded to ten seconds; a healthy full download has no short total-duration timeout. The response uses `no-store` and advertises byte ranges. Single bounded, open-ended, and suffix ranges return exact 206 responses after validating upstream status, total size, Content-Range, and partial length. Unsatisfiable ranges return 416. HEAD ignores Range; malformed/multiple ranges return the full 200 representation. The proxy issues no validators, so requests with If-Range conservatively receive the full representation. The handler forwards only normalized ranges to the fixed media origin, retains attachment filenames, and bounds streaming to the selected length. This supports Safari's two-byte media probe and native View playback on the workspace preview. RSS retains the original direct media URLs; eligible Chromium VBR playback uses the virtual MP4 source described above.

The response service streams chunks and verifies the final byte count. The Node handler uses `Readable.fromWeb` and `pipeline` for backpressure and cancellation; H3 v1's default web-stream bridge does not wait for `write()` backpressure. A client disconnect cancels upstream work. Invalid upstream metadata produces a plain 502/504 before success headers; a failed body terminates the connection without appending an error document.

All 55 known `/podcast/...` paths and their single trailing-slash variants redirect with 301 to the saved episode path. Redirects use the shared publication predicate and drop legacy query parameters. Unknown paths are 404; no title/GUID-derived guesses are made. Existing RSS aliases remain in place.
