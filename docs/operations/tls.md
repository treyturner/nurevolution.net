# Production TLS

Caddy 2.11.4 and the Cloudflare DNS module are pinned in [Caddy.Dockerfile](../../deploy/Caddy.Dockerfile). The tested image is published by digest alongside the app. The initial JSON uses Let's Encrypt staging so setup errors do not consume production issuance limits. Its explicit `apps.tls.certificates.automate` list starts issuance for the canonical website, www, and podcast hosts before application routes exist; automation policy subjects alone only select how certificates are managed. The DNS-01 issuer can validate canonical hosts before their public A/AAAA records move. The delivery gate validates the account-token format and tests early issuance with an offline local CA; public CA issuance remains a live check. Confirm zone ownership and current rules first.

Use an [account-owned Cloudflare API token](https://developers.cloudflare.com/fundamentals/api/get-started/account-owned-tokens/) named `nurevolution Caddy DNS`, created under **Manage Account → Account API Tokens**, with `Zone → DNS → Edit` and `Zone → Zone → Read`, restricted to the `nurevolution.net` zone. These are the [Cloudflare module's required permissions](https://github.com/caddy-dns/cloudflare#configuration). The owner selected an account token in the `cfat_` format; the pinned Caddy module explicitly accepts that format. Keep it in the owner's password manager for recovery and renewal; any expiration requires rotation before it expires.

Install [the credential helper](../../deploy/cloudflare-credentials.py) as root-owned `/usr/local/sbin/nurevolution-cloudflare-credentials`, mode `0700`, and run it interactively on the droplet. It prompts without echoing and creates `/etc/nurevolution/cloudflare.env` with mode `0600`, refusing to overwrite an existing file. It does not contact Cloudflare, change DNS, or issue certificates. Use that file as an additional Compose `--env-file` when starting the edge; keep the verified image's environment file separate. The token belongs only in the edge environment, never in application containers, Git, command arguments, or logs.

Verify an account token with `GET /client/v4/accounts/{account_id}/tokens/verify`, using Bearer authentication, as specified by the [account-token API](https://developers.cloudflare.com/api/resources/accounts/subresources/tokens/methods/verify/). The user-token endpoint `/client/v4/user/tokens/verify` does not apply. Obtain the account ID from the permitted zone lookup or the owner, and separately confirm access to that zone's DNS records. Record only verification status and necessary non-secret identifiers; successful token verification alone does not prove DNS write permissions. Caddy uses the same `CLOUDFLARE_API_TOKEN` environment variable for account tokens and discovers the zone through the DNS provider.

The account token passed a temporary TXT create/read/delete check during bootstrap. Production now has a proxied website A record, proxied www alias, and a direct DNS-only podcast A record. Cloudflare uses Full (strict). Trusted origin certificates and their restored copies passed verification; the edge recovered automatically after the 2026-09-13 droplet reboot. See [maintenance](maintenance.md) and the [M6 cutover record](../milestones/evidence/M06-cutover.json).

Persist Caddy's `/data` and `/config` directories. Add the generated site route, validate the entire edge configuration, and exercise staging issuance. Once staging works, remove the staging `ca` override to use the production issuer; validate/reload, verify certificate chain/hostname/expiry, and record issuance. Never disable TLS verification to make acceptance pass.

Recreate the edge container as an explicit host rehearsal while preserving its state; verify the same trusted certificate and continued application/media routing afterwards. This shared-edge restart is separate from ordinary application deployments and must account for other sites. Check certificate storage permissions and renewal configuration; a fresh certificate alone does not prove a future renewal occurred. Back up encrypted ACME account/certificate data as part of host recovery.

Cloudflare website SSL mode must be Full (strict). Keep feed, APIs, HTML and download redirects out of broad cache rules and bot challenges; preserve origin conditional feed semantics. Leave the media hostname DNS-only. Cache bypass alone does not remove large MP3 transfers from Cloudflare's proxy.

The external uptime workflow checks trusted website-origin, audio, and Headscale certificates and warns within 14 days of expiry. The website-origin check connects directly to `159.89.86.21` with canonical SNI, so the Cloudflare edge certificate cannot hide an origin renewal failure. Update that address when moving the host. A periodic successful handshake is not evidence that renewal has already occurred; inspect Caddy renewal logs when approaching expiry.
