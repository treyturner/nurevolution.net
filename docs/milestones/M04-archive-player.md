## Public pages, data, and SSR

### Routes and presentation model

| Request                                              | Required result                                                                                                                                                    |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/`                                                  | HTTP 200; complete archive list and newest public episode selected, paused. Keep `/` in the address bar; canonical URL is `show.siteUrl`                           |
| `/episodes/<saved-slug>`                             | HTTP 200 for a public episode; render that episode's metadata, artwork, description, and tracks on the server; canonical URL is `show.siteUrl` plus its saved path |
| Unknown, draft, or future episode on a fresh request | HTTP 404 and useful not-found UI with a home link; never silently select the latest episode                                                                        |
| Empty public archive                                 | Root remains 200 with “No episodes are available yet,” show/RSS information, and no playable source or download; explicit episode URLs are 404                     |
| Initial repository/API failure                       | Useful retry/home recovery and an appropriate 5xx status; distinguish failure from an empty archive                                                                |
| Existing session selecting another episode           | Stage the new detail, then commit an accepted navigation; a failed or superseded request cannot replace the current episode or its audio                           |

Use the existing public types. The shared page model contains `show: PublicShow`, `episodes: EpisodeSummary[]`, and `selected: EpisodeDetail | null`. Loading/error state and pending navigation identifiers belong to application state, not canonical content. Do not send the raw catalog, RSS owner settings, provenance, or every episode's full detail in the initial payload.

Load show and list concurrently, then resolve only the requested or first episode's detail. Reuse Nuxt's SSR payload through explicitly keyed `useAsyncData`/`useFetch`; avoid duplicate hydration requests. All selection remains subject to the server's existing published/nonfuture predicate and descending-date/ascending-ID order. Never hard-code a 55-item limit or decide visibility from the browser clock. Refresh a cached detail when navigation requires it; M8 will review publication/cache timing across page requests.

Use a shared named route middleware, `app/middleware/episode.ts`, for both page routes, with loading/staging in `app/composables/useEpisodePage.ts`. On SSR, resolve and seed the request-scoped model **before the persistent layout renders**. Seeding parent state only from child-page setup is insufficient: the parent may already have rendered empty or incorrect metadata. On hydration, reuse that model without starting playback or loading the same source twice.

On client navigation, stage by navigation generation and commit through a successful router navigation hook. Abort/ignore superseded work and clear it on failure. A failed selection leaves the prior route/model/source usable, exposes “Could not load this episode” with retry, and adds no successful history entry. Back/Forward must follow the same selection policy without issuing another push. Distinguish initial 404 responses from recoverable failed navigation inside an existing session.

All model and controller ownership must be per Nuxt application/request. Do not put mutable selected-episode state in module scope or serialize an audio element, adapter, promise, or event listener into Nuxt payloads. A client-only controller is attached after mount to the already-selected serializable model.

### SSR metadata and links

- Root title: `Nurevolution — Podcast archive`; episode title: `<artist> — <title> | Nurevolution`. Use normal escaped head bindings, a plain-text description, and a canonical link resolved against validated `show.siteUrl`, never the request Host header.
- Include `link rel="alternate" type="application/rss+xml"` with `show.feedUrl`, and a visible “Subscribe via RSS” anchor. Do not replace it with an unsupported directory-subscription button.
- Render actual episode links in the initial HTML. Use `NuxtLink` with each saved `path`, preserve modifier-click/new-tab semantics, and disable automatic prefetch of all episode details. Selecting the same episode may update `/` to its canonical path without reloading audio or resetting time.
- Render one current-episode H1, labelled episode/tracklist regions, artist, publication date, and duration when known. Format dates explicitly in UTC so SSR and hydration agree; do not assume IDs/slugs encode presentation dates. Unknown duration gets an honest unavailable label, not `0:00` or `NaN`.
- Render `descriptionHtml` only from the existing validated/sanitized public projection. Keep ordinary Vue escaping for all other strings. Preserve safe links, emoji, apostrophes, and literal `<3`; do not introduce another sanitizer or expose raw import HTML.
- Root and episode pages share the persistent player layout. Page-specific head metadata changes with accepted selection, together with artwork and tracks. An audio element or layout key must never be the episode slug.

## Persistent player and navigation contract

Create `app/layouts/podcast.vue` for the shared archive layout and an `ArchivePlayer.vue` component for the current artwork, metadata, native controls, and media status. Put the single audio element outside the changing `NuxtPage`. Preserve `AppShell`'s skip link and single main landmark; add `NuxtLayout` without nested main elements.

Render native `<audio controls preload="metadata">` without `autoplay`. The controller binds on mount and loads the selected canonical enclosure once. SSR need not set its source; server-rendered content, download, and RSS links remain usable independently. There must be no `Audio` constructor, `window`, or media operation during server rendering. Do not set `crossorigin` merely to play the existing media: ordinary element playback does not require fetching audio into JavaScript.

Extend `app/services/audio.ts` minimally with a read-only snapshot of the state the controller actually needs, such as `paused`, `ended`, `currentSrc`, readiness/error, and current position for verification. Add native events such as `playing`, `waiting`, `emptied`, or `abort` only where the state machine uses them. Keep native seeking/volume inside the browser controls for M4. Preserve independent subscriptions and idempotent disposal.

Put the deterministic controller in `app/services/player.ts`; integrate it through a per-app `usePodcastPlayer` composable/provider. The controller takes an injected adapter, owns source/play generations and subscriptions, exposes observable status, and disposes with the owning layout/application. Routing/data loading must not be hidden inside the low-level audio adapter.

| Trigger                                           | Source / position                                                    | Playback and UI result                                                                                        |
| ------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Fresh root, deep link, refresh, or new tab        | Select requested/latest, load once at zero                           | Paused; zero calls to `play()` before a user action, including hydration and metadata events                  |
| Native Play/Pause                                 | Same episode, preserve time                                          | Reflect actual native events/state; a rejected Play leaves a paused, recoverable state                        |
| Select a different episode while paused           | Accepted target source, zero                                         | Stay paused; do not call `play()`                                                                             |
| Select a different episode during active playback | Accepted target source, zero                                         | Attempt to continue once; show loading while needed, playing only when the browser confirms it                |
| Select the current episode                        | No source reload, preserve time                                      | Preserve playback; avoid duplicate same-path history entries                                                  |
| Back/Forward to another episode                   | Target source, zero                                                  | Continue only if the existing session was actively playing; otherwise pause. No stored per-episode position   |
| Rapid A → B → C                                   | Only the latest accepted selection can control current source/status | Late fetches, media events, and play-promise resolutions/rejections cannot restore A/B or show their metadata |
| User pauses during a transition                   | Latest target may finish loading                                     | Cancel continuation intent and pending starts; remain paused even when readiness arrives                      |
| Natural `ended`                                   | Current episode remains selected at its end                          | Stop; no next episode and no URL change in M4. Native replay remains available                                |
| Media error                                       | Keep selected episode and readable content                           | Clear playing/continuation state; show a concise error and “Retry audio” action plus download link            |
| Retry audio                                       | Reload current source at zero                                        | Paused; retry is not permission to resume after an error. User presses Play to start                          |
| Artwork failure                                   | Audio source unchanged                                               | Show a stable labelled artwork fallback; player, downloads, and tracklist continue working                    |
| Owner unmount / application disposal              | Cancel pending work and detach owned subscriptions                   | Pause audio once, prevent stale callbacks, and leave no duplicate listeners                                   |

Capture continuation intent from real playback before replacing a source; `load()` can itself emit pause/abort/emptied events. Those transition events must not accidentally erase a legitimate continuation, while a later user pause must cancel it. Validate current source/readiness and generation when applying callbacks; attaching a numeric generation to a global event alone does not prove that event belongs to the new resource. An obsolete rejected play promise, including the expected abort from source replacement, must not become the current episode's error. The [media load API](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/load) documents this interruption behavior.

Keep the old episode playing and labelled as current while a replacement detail request is pending. Mark the requested list row busy separately. On accepted selection, update the model and source together; a buffering new episode is not labelled as the old one. Use no timers that repeatedly attempt autoplay. If the browser rejects continuation, show “Press Play to continue” and wait for that gesture.

## Download delivery and historical redirects

### A working download path

Read-only HEAD samples for Ruminate (`wp-484`) and the apostrophe filename on `wp-311` returned HTTP 200, the expected lengths, and `audio/mpeg`, with no `Content-Disposition`. Both advertised byte ranges; no response body or actual range was tested. These observations are recorded in the supplemental evidence. Do not depend on a cross-origin anchor's `download` attribute alone: attachment response semantics matter to browser download handling. [HTML download processing](https://html.spec.whatwg.org/multipage/links.html#downloading-resources)

Implement **`/downloads/<saved-slug>`** in `server/routes/downloads/[slug].ts`, backed by a separately testable streaming response service in `server/downloads/response.ts` and filename/header formatting in `server/downloads/filename.ts`. The public anchor uses this same-origin path and `download`; audio playback and RSS enclosures keep their exact original URLs. Supply a download link in each episode row and beside the selected player; selecting “Download” must not select/restart the episode.

| Concern         | Required endpoint behavior                                                                                                                                                                                                                                                             |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public lookup   | Resolve the saved slug with `contentRepository.find(slug, asOf)`. Unknown/draft/future is 404 before any upstream call. No client-supplied URL, file path, or filename                                                                                                                 |
| Methods         | GET and HEAD only; other methods are 405 with `Allow: GET, HEAD`                                                                                                                                                                                                                       |
| Upstream        | Fetch only the selected asset's exact HTTPS URL on `podcast.nurevolution.net`; reject redirects and credentials. Forward no request cookies, authorization, query string, or arbitrary client headers. Request identity encoding                                                       |
| Validation      | Before sending success headers, require upstream 200, the canonical media type, identity/no content encoding, and the exact canonical Content-Length. Missing/wrong length or type is a 502 with a useful server diagnostic, not a successful corrupt download                         |
| Success headers | HTTP 200; canonical Content-Type/Content-Length; `Content-Disposition: attachment` with quoted ASCII `filename` and UTF-8 `filename*`; `X-Content-Type-Options: nosniff`; `Cache-Control: no-store` for this application fallback                                                      |
| GET body        | Pipe the upstream stream with backpressure; never materialize the full MP3 with `arrayBuffer`, `blob`, or an application buffer. Abort upstream when the downstream client disconnects                                                                                                 |
| HEAD            | Request upstream HEAD, validate the same metadata, return the same success headers without reading or sending an MP3 body                                                                                                                                                              |
| Range requests  | This fallback may ignore Range and return the complete 200 representation; do not advertise range support here or forward a partial body as a full response. Direct media and resumable downloads are M5 checks                                                                        |
| Failures        | Bound connection/header waiting to 10 seconds, returning 504 for timeout and 502 for upstream failures. Cancel resources/timers; use a plain, no-store error without attachment headers. Once streaming starts, terminate a failed transfer and log it; never append HTML to MP3 bytes |

Do not impose a short total-duration timeout on a healthy large download. Detect premature close/length mismatch during streaming so a truncated transfer is not recorded as successful. Keep the fetch/clock/disconnect interfaces injectable for tests, while the production route supplies the real repository, allowlist, and Node transport. Any future allowed media origin must be an explicit server configuration/code change, never a request parameter.

Use `audio.downloadFilename`, the raw canonical basename, rather than decoding the enclosure URL. Reject path separators, CR/LF/control characters, and invalid basenames at the response boundary. Escape quoted header syntax; encode UTF-8 `filename*` correctly, including apostrophes and percent signs, without double decoding. Test ordinary ASCII, the real `bouche_d'incendie` basename, and synthetic Unicode/quotes. [RFC 6266 attachment and filename parameters](https://www.rfc-editor.org/info/rfc6266/)

This endpoint makes M4 functional without modifying the existing Apache host. It is a transfer fallback, not the production capacity design. M5 must preserve `/downloads/<slug>` while offloading mapped media to the droplet's file-serving layer, preserving the attachment filename/type/length contract and public selection rules. Test direct serving, ranges/resume, capacity, and deployed browser saves there. Do not proxy the regular player stream through Nuxt or move MP3s into Git/the application image.
