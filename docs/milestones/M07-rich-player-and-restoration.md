## Outcome and review decisions

Deliver one persistent, accessible player with custom playback/seek/volume controls, seekable timed tracks, position-based highlighting, older/newer episode controls, automatic sequencing, and local restoration within a 24-hour visit window. Fresh documents always start paused, including restored positions and explicit episode links.

The following choices are the implementation contract accepted by the owner's instruction to implement M7. Earlier owner-confirmed behavior is identified separately from decisions proposed in this plan. There are no unanswered product or architecture questions required to begin implementation.

| Area            | Decision                                                                                                                                                                                                                                                               |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Playback        | Preserve the owner's paused-on-load rule and active/paused selection behavior. One existing audio element serves the entire session. No player library or additional runtime dependency.                                                                               |
| Restoration     | Remember one current episode ID and position. A valid explicit episode URL wins; restore its position only when its ID matches the saved record. A valid root-page restore replaces `/` with the saved episode's canonical path.                                       |
| Visit window    | Expire at exactly 24 hours since the last document visit, independently of position writes. Initial loads, reloads, new tabs, and returning a document from the back/forward cache count; internal route changes and tab focus do not. Never expire a running session. |
| Multiple tabs   | Each tab plays independently. Save progress from actual local activity; the last completed eligible write supplies the next visit's restore record. Storage changes never select, seek, play, or pause another tab.                                                    |
| Seek and volume | Native HTML range inputs inside custom controls. Seek bar, ±30 seconds, and timed-track seeks use browser duration and preserve playback intent. Show volume only when element-volume control works; retain mute independently where supported.                        |
| Tracks          | D01: a track click seeks and remains paused unless already active. Previous uses the exact three-second rule. Navigation skips untimed rows and stays inside the episode. Highlight only intervals whose boundaries are supported by the track data.                   |
| Episodes        | D02: Previous always means older; Next always means newer. Both wrap. Automatic playback defaults to newer-to-older and follows the selected direction; the direction control never reverses manual buttons.                                                           |
| History         | Manual episode navigation pushes; successful restoration and automatic advancement replace; Back/Forward consumes history. Seeks, time updates, direction, and volume never change the URL.                                                                            |
| Preferences     | Direction, volume, mute, and last nonzero volume persist only within the mounted player, including episode changes. They are not added to the 24-hour saved record. Default direction is newer-to-older on each new document.                                          |
| Interface       | Keep the current artwork, branding, copy/download/RSS links, mobile Episodes/Tracklist tabs, and desktop adjacent lists. Place custom controls in the existing player area; no redesign or new mobile layout experiment.                                               |

M8 drafts/scheduling, M9 timestamp links/Media Session/feed chapters/palettes/hosting changes, playback-speed controls, shuffle, queues, per-episode listening history, accounts, analytics, and cross-device sync are outside M7. Canonical content, feed identity, public API response shapes, media URLs, and deployment topology need no change.

`PlayerSnapshot` includes selected source ID, existing status, desired playback (`paused` or `playing`), confirmed current time and finite duration or `null`, readiness/seeking, pending seek target or `null`, volume/muted/capabilities, and a recoverable seek message. It contains no DOM objects or promises. Keep existing media status distinct from a failed seek: one rejected seek does not make readable content or otherwise working audio unusable.

Selection options identify `initial`, `manual`, `history`, `restore`, `automatic`, or `retry`, plus any initial position and generation-scoped continuation token. Regular same-ID selection remains a no-op; explicit replay and single-episode automatic restart use a separate restart operation. Refreshing detail for the same ID and unchanged audio URL updates presentation without a load. If its audio URL changes, treat it as a new source generation, start at zero, and apply the same active/paused rule.

Keep three distinct tokens: source generation, play-intent generation, and navigation generation; pending seeks also carry a latest-request token. A later pause invalidates playback authorization immediately, even during a fetch or seek. A late callback cannot change current metadata/status or restart audio. If an obsolete play settlement leaves the current element running while current intent is paused, pause it; do not pause a newer authorized play. Check current source/readiness as well as tokens, since a queued native event does not carry a reliable resource ID.

## Playback and route transitions

“Active” means a current, uncancelled playing intent backed by an accepted Play request or real playback, including buffering. Initial loading alone is not active. Media errors, blocked/rejected playback, retry, and an explicit pause clear continuation intent. The native end-of-media pause must not clear an otherwise eligible automatic-advance token before `ended` is processed.

| Trigger                                                                   | Source / position                                                     | Playback and route result                                                                                                                                                                |
| ------------------------------------------------------------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fresh document, including refresh/new tab                                 | Resolve the explicit/latest/restored target below; load paused        | Zero calls to `play()` until a user action. SSR has no audio or storage effects.                                                                                                         |
| Play                                                                      | Current source and position; explicit replay at its end seeks to zero | One authorized request; show Pause while pending so the listener can cancel. Confirm “Playing” only from browser state. A queued restore seek completes before native Play is attempted. |
| Pause, including during fetch/loading/seek                                | Keep current position and any already accepted target                 | Synchronously invalidate pending starts/automatic continuation and pause. A later accepted navigation may load its target, paused.                                                       |
| Different episode selected by list, Older/Newer, or Back/Forward          | Stage detail, then accepted target at zero                            | Preserve active/paused intent at commit; a pause while staging wins. Manual pushes; history never pushes again.                                                                          |
| Same episode selected                                                     | Preserve source and position                                          | No reload/restart. Root-to-canonical navigation is allowed without restarting. Same-path actions add no entry.                                                                           |
| Track click, ±30 seconds, seek slider                                     | Same source, clamped seek target                                      | Preserve current intent; paused seeks call no Play. No route change.                                                                                                                     |
| Direction control                                                         | Same episode/time                                                     | Change only the direction used at the next eligible end; no navigation/play call.                                                                                                        |
| Eligible natural end                                                      | Current source reaches its end under active intent                    | Consume one end token, resolve the neighbor, replace the route on success, and attempt continuation at zero.                                                                             |
| End reached by seek while paused, restore at end, stale/duplicate `ended` | Keep current episode                                                  | No automatic advancement or Play. Play explicitly restarts the current episode.                                                                                                          |
| Active user seek exactly to the end                                       | Current source at duration                                            | Treat confirmed end as one eligible advance; cancel any pending seek feedback before committing the next source.                                                                         |
| Media or navigation failure                                               | Keep accepted episode and readable content                            | Media errors clear continuation and offer Retry audio; failed navigation preserves prior route/source and existing navigation retry. No skip-through loop.                               |
| Retry audio                                                               | Reload current source at zero                                         | Paused, clear pending restoration/seek and continuation. Preserve in-session direction/volume.                                                                                           |
| Disposal or leaving the document                                          | Save eligible pending progress; invalidate callbacks                  | Pause and clean up owned listeners/timers once. Returning via back/forward cache never calls Play.                                                                                       |

An already pending manual/history navigation takes priority over automatic end handling; do not replace its target with the automatic neighbor. If the old source ends during that fetch, preserve its previously active continuation token for the pending navigation unless paused/cancelled. A later explicit navigation supersedes an automatic fetch. Failed automatic navigation stays at the ended episode with the existing “Could not load this episode” retry; retrying that navigation is manual and loads paused. There is no background retry or skipping to additional episodes.

## Restoration and persistence

### Stored data and visits

Use two origin-local keys, with no cookies or server writes:

```ts
// nurevolution.playback.visit.v1
{ schemaVersion: 1, lastVisitedAt: number }

// nurevolution.playback.resume.v1
{ schemaVersion: 1, episodeId: string, positionSeconds: number, updatedAt: number }
```

Times are epoch milliseconds; position retains fractional seconds. Accept only the exact version and fields with finite nonnegative numeric values and a nonempty valid episode ID. Reject negative/nonfinite positions, malformed JSON, unknown versions, and timestamps in the future relative to the injected current time. Limit either stored string to 2 KiB before parsing. Read/access/write/remove failures are caught and disable persistence for that document; listening continues without a blocking dialog. Never call `localStorage.clear()`.

Read the previous visit and resume records **before** recording the new visit. The record is eligible only when `0 <= now - lastVisitedAt < 86_400_000`; exactly 24 hours is expired. `updatedAt` orders progress activity and does not extend expiry. Missing/invalid visit data makes resume unusable. Remove expired/invalid owned data best-effort, then record the visit even when there is no usable resume state. Do not start an expiry timer.

Count each initial document once at client initialization, including a background tab. Do not double-count its later initial `pageshow`. A `pageshow` with `persisted: true` records a new visit, keeps that document's current episode/time, and remains paused; it does not reapply storage or expire the retained session. Pause on `pagehide`, not on ordinary `visibilitychange`, so background listening can continue. Prerendered documents defer visit/storage work until activation. Internal SPA route changes, focus, becoming visible, playback ticks, and volume changes do not count as visits. This is a chosen product rule built around the documented [pageshow lifecycle](https://developer.mozilla.org/en-US/docs/Web/API/Window/pageshow_event).

### Initial route precedence and bootstrap

| Initial request / saved data                    | Selected episode and position                                                              | Address / failure behavior                                                                                                                                    |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`, no usable record                           | Newest server-eligible episode at zero                                                     | Keep `/`; empty archive remains the existing empty 200 state.                                                                                                 |
| `/`, valid saved ID still in public list        | Saved episode, saved position after metadata                                               | Stage its detail and `router.replace` its saved canonical path, including if it is already the newest episode. No new history entry.                          |
| Explicit public episode matching saved ID       | Requested episode, saved position after metadata                                           | Keep requested route; canonical metadata uses the saved episode path.                                                                                         |
| Explicit public episode different from saved ID | Requested episode at zero                                                                  | Keep route. Do not fetch or select the saved episode.                                                                                                         |
| Invalid/unknown/draft/future explicit episode   | Existing real 404                                                                          | Storage cannot turn it into a successful root or remembered-episode response.                                                                                 |
| Saved ID removed/unpublished or expired         | Newest eligible episode at zero on `/`; requested public episode at zero on explicit route | Discard the unusable record; never resurrect an episode from stored data.                                                                                     |
| Saved detail fails after appearing in the list  | Retain newest root episode, paused                                                         | Bound the restore detail attempt to five seconds; abort/ignore its late result. Show “Saved episode could not be restored.” Do not change the URL on failure. |

SSR remains deterministic: render the root's newest public episode or the explicit episode, with complete links/metadata and no personal state. After hydration, resolve restoration before the first audio-source load. Keep SSR content visible with “Restoring your place…” during a root detail request; disable playback controls until it settles, while episode links remain available. A user selection cancels pending bootstrap restoration and loads their accepted target paused. Restoring the same explicit episode reuses the initial detail and makes no second detail request. Never render personal restoration state into a shared server response.

Apply a pending saved position only after the current source reports metadata and a finite positive browser duration. Clamp it to `[0, duration]`; an at/beyond-end position restores at the end, paused, without sequencing. Do not round timestamps for logic or substitute stale catalog duration. A ten-second metadata retry retains the pending restore target for that same logical source; explicit Retry audio discards it. Paused loading/delay feedback remains available if metadata never arrives.

If Play is pressed while a restore seek awaits readiness, queue that user intent, expose Pause immediately, complete the seek, then attempt Play once. If the browser rejects the deferred request, show the existing blocked prompt and require a new gesture. A user seek replaces the pending restore target; a new episode selection discards it. A failed restore seek leaves the actual position visible and shows “Saved position could not be restored”; it does not silently claim success.

### Progress writes and tab behavior

- Keep only the most recent episode/position. After successful bootstrap selection/restoration settles, write that selected record once; do not overwrite a pending saved position with a temporary zero during loading. If a restore fetch fails, leave its prior resume record intact until the listener acts.
- Capture progress from current-source `timeupdate` while actively playing; persist at most once every five seconds. Save immediately on accepted user episode selection, completed user seek, pause, eligible end, and accepted automatic advancement. Read back actual media position after seeks; source-reset zeroes must not overwrite the old episode's position or a pending restore target.
- Flush an already dirty record on `visibilitychange` to hidden, `pagehide`, and disposal. Preserve the timestamp of the actual position/selection activity, not the flush time. A paused tab with no new activity does not write merely because it is hidden or closed. Native teardown pauses are not new listening activity.
- Before flushing, read the shared record and skip a candidate whose activity timestamp is older than the stored one. Equal timestamps use last completed write. Storage operations are not a cross-tab transaction: simultaneous activity may resolve by physical write order, which is acceptable for one resume slot. Do not add locks, an ownership lease, or a listening-history database.
- Other tabs' storage events may update the last-seen persistence bookkeeping only. They never alter a running tab's episode, position, volume, direction, or playback. Two tabs may play at once. A newly opened tab restores the last completed eligible shared write and starts paused. The [storage event contract](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event) makes same-origin sharing explicit.
- Storage is origin-specific: production, local development, and any test origin have separate state. Store the stable ID, never a host, slug-derived identity, audio URL, playing flag, volume, or direction. An older release safely ignores these additive keys; future incompatible schemas must use a new version.

## Seeking, progress, and volume controls

### Seek contract

Use `currentTime` assignment through the adapter, not `fastSeek`, so precise imported starts remain the requested values. The browser determines the final supported position; reconcile from its snapshot and `seeked`/`timeupdate`. The [HTML seeking algorithm](https://html.spec.whatwg.org/multipage/media.html#seeking) and [currentTime API](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/currentTime) define that boundary.

- Seek bar and ±30-second controls are disabled until the current source has a finite positive browser duration and no fatal media error. Known timed-track commands may queue a seek before metadata; the last requested target wins. No command seeks using an old source's duration.
- Finite user targets clamp to `[0, duration]`. For disjoint nonempty native seekable ranges, choose the closest supported point, breaking ties toward the earlier point. Do not clamp to `buffered`: seeking may request an unbuffered byte range. If `seekable` is empty, allow the native attempt after metadata rather than permanently disabling a browser that has not exposed ranges yet.
- ±30 seconds is measured from actual current time or the latest pending seek target during repeated clicks. Clamp each result; preserve active/paused intent. Disable backward at zero and forward at duration. Invalid/nonfinite commands are no-ops with no media call.
- Pointer scrubbing previews time and `aria-valuetext` without repeatedly seeking or pausing audio. Commit once on release/change; keyboard changes commit once per key operation. Escape/pointer cancellation reverts the preview. While scrubbing, incoming time ticks do not move the thumb. An accepted source change or error cancels the old scrub. A natural end may proceed normally and cancels any old-source preview.
- Reconcile a successful seek from the current snapshot, allowing 250 ms position tolerance in integration checks. Unit navigation math uses exact values. Catch assignment errors; if a seek remains unconfirmed after five seconds, clear its pending UI and show “Could not seek. Try again.” A late actual seek result updates the real position and clears that message. Never reload or repeatedly seek on a timeout.
- A duration change recomputes bounds, clamps any pending target once, and invalidates track starts outside the actual media. Unknown/zero/nonfinite duration means unavailable seek bounds; display `—:—` in the progress control and keep the existing loading/retry behavior. The separate publication metadata may still display catalog duration.

Keep the progress view driven by native events; no animation-frame timer or simulated progress clock. Render elapsed and total time with the existing formatter, adding a spoken-time helper for accessible values. Seeking updates progress/highlighting from confirmed position, except for the slider's explicitly temporary preview.

### Volume and mute

Volume capability is separate from touch layout and mute support. On the existing element, before any playback request and while paused, probe a different in-range volume and read it back, then restore the original value in `finally`. Probe mute separately under the same paused conditions. Suppress probe-generated persistence/announcements and never perform an audible active-playback probe. Exceptions or ignored writes mark that capability unavailable. Reconcile all later user writes from actual values; a failed write removes the corresponding control and exposes its fallback. The [volume API](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/volume) has limited cross-browser support, so property presence alone is insufficient evidence.

Supported volume uses `0..1`, displayed as `0..100%`, in 5% keyboard steps. Mute changes `muted` and preserves the previous nonzero volume. Moving volume above zero unmutes. Muting at zero remembers the last nonzero value (default 1); Unmute at zero restores that value. Reflect `volumechange`, including changes made outside the custom UI. A volume slider indicates element volume only, not the device's master volume.

Where element volume is unavailable, omit its slider and reserved space and show “Use your device's volume buttons.” Keep a working mute control independently; if mute is unavailable too, omit it. Capability detection cannot prove physical loudness behavior: verify it on the actual Android and iPhone browsers before claiming device acceptance. No Web Audio workaround or platform-volume emulation.

### Layout and accessibility

Replace the native control UI after the client session attaches successfully; keep one audio element with no `autoplay` or native `loop`. Render the native fallback during SSR and before attachment; set `controls=false` only when custom controls are ready. The existing SSR audio has no source, so no-JavaScript listening still uses the ordinary download link. If attachment fails, preserve the fallback and readable page. Remove the Chromium native-volume pseudo-element overrides when custom controls are enabled.

Within the current player content area, use a full-width elapsed/seek/total row, then a wrapping row ordered Previous track, Back 30 seconds, Play/Pause, Forward 30 seconds, Next track. A separate wrapping row contains Older episode, Newer episode, and a labelled two-option “Automatic playback order” select: “Newer to older” and “Older to newer.” Put supported volume/mute below without reducing the seek row's width. Keep playback status, Retry audio, and Download MP3 below the controls. Use existing colors, spacing, and typography.

Use real buttons and range inputs, visible text for older/newer/direction, and accessible names for transport icons. Seek arrows change five seconds; Home/End go to zero/duration; Page Up/Down change 30 seconds. Volume arrows change 5%; Home/End use 0/100%. Buttons support normal Enter/Space; do not add global keyboard shortcuts. The seek value is spoken as elapsed time “of” duration, rather than raw seconds. Slider interaction follows the [W3C slider pattern](https://www.w3.org/WAI/ARIA/apg/patterns/slider/), with physical touch-assistive-technology checks included below.

Controls have at least 44 px touch targets and visible keyboard focus. At 320 px and 200% text size, rows wrap without horizontal page scrolling. Disable controls honestly for empty archives or unavailable destinations; Play remains usable during ordinary delayed metadata except the bounded root restore bootstrap. Keep the existing single episode-selection announcement; announce a new seek failure once, never each progress tick or automatic track highlight. Associate playback status with the control group. Do not move focus or switch mobile tabs on seeks or automatic progression.

## Timed-track navigation and highlighting

Use source-order tracks with finite known starts; do not round away fractional seconds. Once browser duration is known, exclude starts at or beyond it from navigation and highlighting, retaining their original text in the list. Untimed or out-of-range rows remain readable without a seek button; before readiness, known starts are buttons capable of queueing a seek. Accessible button names include track number, artist/title, and start time. Preserve all 832 rows and empty-list messaging.

Let `K` be navigable known starts in order and `anchor(t)` the last known start at or before confirmed time `t`. Track navigation remains useful even in a gap whose precise current track is unknown.

| Condition / action                        | Destination                                                                                           |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| No navigable starts                       | Previous/Next track disabled; no highlighted row.                                                     |
| Before the first known start              | Previous track disabled; Next track goes to the first known start. Do not synthesize a track at zero. |
| Previous, `t - anchor(t) > 3`             | Restart that known start.                                                                             |
| Previous, `t - anchor(t) <= 3`            | Previous known start; if none exists, restart the first known start.                                  |
| Next with a following known start         | Next known start strictly after the current anchor.                                                   |
| Next at/after the final known start       | Disabled; no episode change or track wrap.                                                            |
| Click the current timed track             | Explicitly seek to its start, including while paused; this differs from same-episode selection.       |
| Rapid track actions during a pending seek | Compute from the latest requested target; the final request wins.                                     |

At `start + 2.999` and `start + 3.000`, Previous goes to the preceding known start; at `start + 3.001`, it restarts the current one. Apply the comparison to the reported media time without an epsilon or display rounding. Only browser integration assertions use a tolerance.

Highlight track `i` for the half-open interval `[start_i, start_(i+1))` when the immediately following source row is timed. A final source row with a known start remains highlighted through the episode's end. Before the first known start there is no highlight. If a timed row is followed by one or more untimed rows, its ending boundary is unknown: leave that interval unhighlighted until another supported interval begins. Do not guess the untimed track or extend a “current track” label over unknown boundaries. Navigation still skips those untimed rows using `K`.

Apply a visible non-color-only marker and `aria-current="true"` to the supported current row; this denotes position even while paused, not a claim that sound is playing. No auto-scroll, focus movement, or live announcement on time ticks. Mobile track buttons use the same session even when the player and list are in separate components; changing tabs does not replace any media listeners.

## Episode navigation and automatic sequencing

Use only the server-returned ordered public summaries; never import the full content catalog into the browser or re-evaluate publication dates using the browser clock. Given newest-first array length `N` and selected index `i`, older is `(i + 1) % N`, newer is `(i - 1 + N) % N`. Ties follow the supplied order.

| Archive condition                    | Manual buttons                                                                                                                | Eligible automatic end                                                                                      |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Two or more episodes                 | Older/Newer wrap using those formulas; target starts at zero                                                                  | Newer-to-older chooses older; older-to-newer chooses newer. Replace history on successful route commit.     |
| One episode                          | Both enabled; explicit older/newer restarts this episode at zero, preserving active/paused intent; no duplicate history entry | Restart the same source at zero and play once per genuine completion. No route change and no native `loop`. |
| Empty list                           | Both disabled; no playable selection                                                                                          | No action or retry loop.                                                                                    |
| Selected ID absent from current list | Both disabled until a later successful data refresh supplies a valid selection                                                | Stop at end; do not guess a neighbor or resurrect a missing episode.                                        |

Resolve neighbors from the latest accepted page model at the time of action. During pending navigation, ignore repeated Older/Newer activations and expose busy state; direct list selections may supersede the request. A direction change during an already pending automatic navigation affects the following end, not the target already chosen. Continue to use fresh public detail resolution for the candidate target; a 404/failure stops that attempt and stays recoverable. No background polling, speculative audio preload, automatic list refresh at the boundary, or M8 scheduling work is added.

The low-level controller emits an eligible end at most once per playback run of a source. Arm it only after real active playback; consume it before navigation begins. Re-arm on an explicit Play/restart that reaches active playback. Programmatic paused seeks, duplicate events, detached listeners, and late events from older sources cannot arm it. An explicit Pause while automatic detail is loading or the next source is buffering cancels continuation; the pending target may finish committing, paused. A rejected Play displays “Press Play to continue” and ends automatic attempts until the listener acts. Script-initiated continuation remains subject to the browser's [play promise and permission behavior](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play).
